# Troubleshooting

**OrbStack / Colima / Docker**: Start the selected engine and set `dockerContext` in ignored `config/local.json` to its name from `docker context ls`: `orbstack` (the default), `colima`, or a named Colima profile such as `colima-demo`. No environment override is needed. Test `docker --context <context> info` and `docker --context <context> compose version`. The launcher always passes this context explicitly, leaving your global context unchanged. See the [runtime setup instructions](../README.md#choose-a-container-runtime) for installation and Compose plugin setup. Stop the demo before changing engines; each engine has its own images and volumes.

**Images / memory**: Initial pulls may take several minutes. From `perf-agent/`, check `docker --context <context> compose -p perf-agent-demo logs lgtm`, replacing `<context>` with the configured engine. `grafana/otel-lgtm` is intended for development/test, not production. For Colima, start with 4 CPUs and 6 GiB of VM memory, plus host memory for Chrome and Node. Keep the checkout within a shared Colima mount and retain its `host.docker.internal` mapping so the collector can scrape ports 4100–4102 on the Mac. Stop other heavy jobs for comparable benchmarks. Missed offered-load slots deliberately block performance validation.

**Codex**: `codex --version` must report 0.155.1 or newer; `codex login status` must show a login. `npm run test:protocol` verifies the real handshake without spending a model turn. This project uses a separate `.local/codex-home`, reusing the existing file-backed authentication by symlink. If your installation stores credentials only in another mechanism, run `CODEX_HOME="$PWD/.local/codex-home" codex login` explicitly. Do not copy tokens into config. A model-access error can be corrected with an available `model` in `config/local.json`; restart and reset to start a new budget.

**CLI upgrades**: Regenerate schemas into a temporary directory with `codex app-server generate-json-schema --out /tmp/perf-protocol-new` and `generate-ts`. Newer CLI versions pass the minimum-version check automatically. When checking compatibility, review handshake, thread/turn, approval, notification and token-usage differences, and rerun unit tests and the real protocol/end-to-end checks. Update the baseline schemas and minimum version only when the integration requires newer functionality.

**Browser**: Chrome 149+ is needed for MCP URL restrictions. Each incident uses `.local/chrome/<incident>`, never the presenter's normal Chrome profile. Chrome MCP disables usage statistics and CrUX calls. Screenshots/file-writing tools are rooted in that worktree's `evidence/` directory. Browser failures are visible in real tool results; required-tool gates prevent declaring the investigation complete without evidence.

**Ports**: 4310 dashboard, 4100 deployed app, 4101 candidate, 4102 benchmark baseline, 54329 PostgreSQL, 3001 Grafana, 9091 Prometheus, 4318 collector, 3101 Loki, 3201 Tempo. Preflight rejects conflicts; it never kills the owner. Use `lsof -nP -iTCP:<port> -sTCP:LISTEN` to identify a process. Stop it yourself or adjust the versioned URL/Compose adapter consistently. No automatic random port changes.

**Telemetry**: Start Traffic, wait for exports and the configured window. Inspect app `/metrics`, Prometheus `/api/v1/query`, and collector logs. `insufficient` means fresh exporter but too few observations; `unavailable` means stale or failed telemetry. Never interpret either as healthy. New deployments intentionally need new samples. In Grafana select the latest deployment and appropriate 30s/300s window. Browser traces are Chrome performance traces; distributed traces are stored in Tempo.

**Blocked agent**: Read the error and actual tool details. Approval escalation is denied by policy; it is not a silent permission grant. Cancel sends `turn/interrupt`. Retry resumes the same worktree/thread and phase, with bounded attempts and the original deadline. Unknown thread-creation outcomes require inspection/reset rather than starting another thread. A failed correctness/performance check remains blocked, even if Codex claimed success.

**GitHub**: Use a dedicated application repository, existing `gh` authentication, and the setup commands in README. Configure the exact same remote string for `demo-target` and `targetRemote`. The affected `demo-regression` base must already exist remotely and match the incident revision. The publisher never creates repositories, force pushes, merges or deploys. An error after PR creation is reconciled with `gh pr list` on retry.

**Stop / reset / crashes**: Clean shutdown owns and stops its child processes, then runs Compose down without removing volumes. A lifecycle lock blocks duplicate launchers. After a hard kill, inspect `.local/runtime.json`, `.local/run.lock/pid` and `ps`/`lsof`; only stop processes whose command and working directory belong to this project. Do not blindly kill by port or delete all Docker volumes. `npm run demo:stop` can stop the project’s containers when no controller remains. State, branches, worktrees and evidence are preserved. Remove stale lock files only after confirming their PID is dead; the launcher normally detects this itself.

**Reset with valuable edits**: Online reset does not touch application worktrees or branches. Offline reset archives SQLite and removes only owned fixture/telemetry volumes. Evidence is private and retained. Remove old `.local/results`, releases or worktrees manually only after reviewing/archiving what you want to keep; no automatic garbage collection discards edits.
